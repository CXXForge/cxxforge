# CXXForge Governance

## Purpose

This document describes how the CXXForge project is currently organized and how technical and community decisions are made. Governance will evolve as the project gains maintainers and contributors.

## Current project phase

CXXForge is in its foundation and architecture phase. The project is currently stewarded by its founder and organization owner. The project does not yet have a formal maintainer council or elected governance body.

## Roles

### Founder / project lead

The founder currently stewards the project direction, repository administration, release planning, and maintainer appointments. This role is not a permanent guarantee of unilateral authority over future community governance.

### Maintainers

Maintainers are trusted contributors authorized to review and merge changes, manage issues, and help uphold project standards. Maintainer responsibilities and access should be documented as the team grows.

### Contributors

Contributors participate through issues, discussions, RFCs, documentation, tests, and code changes. Contributions are subject to the repository's contribution and review processes.

## Decision-making

- Routine implementation decisions may be made in issues and pull requests.
- Significant architectural or specification changes should use the RFC process.
- Accepted architectural decisions should be recorded as ADRs.
- Decisions should consider correctness, security, interoperability, maintainability, and long-term ecosystem impact.
- Technical disagreement should be resolved through evidence, documented trade-offs, and maintainer judgment.

## RFC and ADR relationship

An RFC is a proposal for discussion before a significant change is accepted. An ADR records an architectural decision and its consequences. An accepted RFC may result in one or more ADRs.

See [rfcs/README.md](rfcs/README.md) and [docs/architecture/decisions/README.md](docs/architecture/decisions/README.md).

## Changes to governance

Governance changes should be proposed transparently, discussed with affected contributors, and recorded in the repository. As the project grows, this document should be updated to define maintainer selection, succession, voting or consensus rules, conflict resolution, and release authority.

## Project ownership and trademarks

The GitHub organization and repository are the current project coordination points. Use of the CXXForge name and visual identity does not imply endorsement by the project. A separate trademark policy may be adopted if the ecosystem requires one.
